[[introduction]]
== Introduction

Jakarta CRaC (Coordinated Restore at Checkpoint) defines a standard behavior
for Jakarta EE applications and runtimes for checkpoint and restore events.

Checkpoint and restore mechanisms, such as those researched by the OpenJDK
CRaC Project and provided by OpenJ9 CRIU support (InstantOn), make an image
(snapshot) of a running Java instance and later start new instances from that
image. Restoring from an image can address problems with the start-up and
warm-up times of Java applications. Jakarta CRaC defines how a Jakarta EE
runtime is made aware that a checkpoint is being taken and that it is being
restored, and how application developers tell the runtime to handle the
external resources used by the application.

[[scope]]
=== Scope

* Defines how a Jakarta EE runtime is notified of checkpoint and restore
  events.
* Defines the obligations of a Jakarta EE runtime towards the resources it
  manages when a checkpoint is taken and when the runtime is restored.
* Defines how applications make the runtime aware of resources to manage at
  checkpoint and restore events.
* Defines both automatic checkpoints and manual checkpoints that are
  triggered from outside the Java Virtual Machine.
* Defines CDI events and annotations for checkpoint and restore events.

[[goals]]
=== Goals

The primary goals of Jakarta CRaC are:

**Runtime notification**:: Provide a standard mechanism to notify Jakarta EE
implementations about checkpoint and restore events.

**Application resources**:: Provide a standard mechanism for Jakarta EE
applications to make implementations aware of resources to manage at
checkpoint and restore events.

**Mechanism neutrality**:: Work seamlessly with CRaC and InstantOn.

[[non-goals]]
=== Non-goals

The following are explicitly outside the scope of this specification:

**Replacing the CRaC API**:: This specification does not seek to replace the
existing CRaC API (`org.crac`).

[[terminology]]
=== Terminology

Checkpoint:: The act of making an image of a running Java instance.

Restore:: The act of starting a Java instance from an image created by a
checkpoint.

Image:: The persisted state of a Java instance produced by a checkpoint.

Runtime:: A Jakarta EE implementation, such as an application server, that
implements this specification.
